## Conclusion

The historical **16 logical groups / 42 tests** remain an identifiable need
list. They are not a claim of complete coverage: **14 passed, 28 failed for
missing input files**. None of those 28 is validated by its failure. New
packaged fixtures cover useful capabilities, but replacing a historical
reference requires an explicit capability-level decision.

Categories used below:

- **V — versioned fixture:** committed to the repository.
- **C — external corpus:** locally obtained, not committed.
- **R — external reference:** generated by a separate tool such as NMRPipe.

Independent decoding of a binary/text file is distinct from comparison with
vendor-software output. A writer round trip can detect regressions but can
also share reader/writer assumptions; it is not an independent format oracle.

## Manifest completeness, rights and integrity

The [manifest](../testdata-manifest.toml) and
[verifier](../../scripts/verify_testdata.py) describe the external corpus.
Their existence and checksum success do not prove all test dependencies are
inventoried:

- `agilent_*` groups can be marked complete even though conversion tests need
  missing `test.fid` references not listed or declared missing.
- `bruker_1d`/`bruker_2d` mention absent pdata but not all conversion references.
- RNMRTK conversion-reference paths must be reconciled with the two declared
  missing groups. Only Bruker 3D inventories its derived Pipe reference files.
- Packaged fixtures are outside this manifest. Forty documented hashes match;
  the audit found no recorded hashes for the other 82 files and no automated
  fixture-hash enforcement. Git tracks their contents; any additional checksum
  scheme should serve provenance/download verification, not merely duplicate Git.

Historical archive:
[nmrglue v0.5 test data](https://github.com/jjhelmus/nmrglue/releases/download/v0.5/test_data_v0.5-dev.zip),
SHA-256 `dbff258fe08a19f1cd08f44b731d3d19e20e54fbb1415d904cd6d03f25209dae`.
The repository's BSD license does not by itself resolve the archive's data
redistribution scope. The manifest records `UNRESOLVED`, not a finding that
redistribution is forbidden.

Likewise, generating a reference with NMRPipe does not by itself prove that
the output is non-redistributable. Assess source-data rights, software use
conditions and any applicable output-distribution terms separately. Earlier
local notes used "unlicensed/non-redistributable" too categorically; the
supported shared conclusion is **rights unresolved**. Generate in disposable
copies and record commands/tool versions before considering corpus updates.

## Other recorded validation limits

- NMRPipe historical file-I/O dataset tests (25), Spinsolve/RS2D/Tecmag and
  lower-priority dimensional variants are outside the 42-test critical set.
  Tecmag's external test passed; five Spinsolve tests lacked data; RS2D skipped.
- Symmetric-tolerance work (#29, closing #17) did not change the expected
  dataset values. Four affected critical Bruker-pdata/JEOL tests remain
  unexecuted. Integration's autonomous float64 bound is `data.size * eps`;
  intentional Tecmag sign and Spinsolve interval checks were retained.
- Corpus isolation (#27) protects Bruker 3D conversions: work on `tmp_path`
  copies, create `acqu3s` there, and leave canonical data untouched. Prior
  validation covered both conversion orders with checksums. Existing
  `FDDMXVAL` comparison exclusion is a limitation, not a validated value.

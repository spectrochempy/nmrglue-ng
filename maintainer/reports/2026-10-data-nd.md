### One-dimensional transpose

Before #56, both `transpose()` and `transpose(0)` raised
`TypeError: an integer is required`; `transpose((0,))` worked. NumPy accepts
all three with unchanged order and values.

The reversed range of one axis is not empty: it contains `0`. Unconditionally
unwrapping any one-element axes sequence converts it to scalar `0`; iterating
over that scalar fails. The fix distinguishes integral scalar arguments from
an outer wrapper around a sequence using `numbers.Integral`.

An early tuple/list-only guard was rejected because it narrowed existing
support for ndarray/range/other iterable arguments. Tests cover the calling
forms, sequence arguments, multidimensional behavior and invalid-axis cases.
The initial implementation notes did not identify an independent session
sufficiently to close the review requirement. The subsequent independent
review recorded below supplies that evidence for #56.

### Integer-axis validation

Before #57, `int()` silently accepted `0.5` and `0.0` as axis zero in
`swapaxes()` and in iterable/multiple-argument forms of `transpose()`.
Replacing it with `operator.index()` rejects non-index values while retaining
Python and NumPy integer inputs. `transpose()` also narrows the caught
exception to `TypeError`.

This intentionally changes behavior for invalid inputs; it is not merely a
documentation cleanup. Review should check both axes, both methods, negative
axes and interaction with #56's scalar/sequence guard.

### Boolean-axis qualification

The reviewer flagged Python Boolean axes without treating them as blocking.
A targeted follow-up during this documentation update confirmed the precise
distinction on NumPy 2.5.3, using `DummyDataND(fshape=(2, 3))` from the
base-class tests and `np.arange(6).reshape(2, 3)`:

| Call | data_nd | NumPy |
|---|---|---|
| `transpose(False, True)` | Accepted, shape `(2, 3)` | `TypeError` |
| `transpose((False, True))` | Accepted, shape `(2, 3)` | `TypeError` |
| `swapaxes(False, True)` | Accepted, shape `(3, 2)` | Accepted, shape `(3, 2)` |
| `transpose(np.bool_(False), np.bool_(True))` | `TypeError` | `TypeError` |
| `swapaxes(np.bool_(False), np.bool_(True))` | `TypeError` | `TypeError` |

This qualifies broad statements of NumPy compatibility: Python `bool` and
`np.bool_` are different cases. Practical impact was not measured; no claim
that callers never pass Boolean axes is needed to preserve the review's
approval. No Boolean-axis behavior or regression test is changed by this
documentation update.
